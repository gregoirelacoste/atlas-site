Les panneaux et les modules

Composer son espace de lecture, déplacer les vues et retrouver sa disposition sur cette machine.

Composer son espace de lecture, déplacer les vues et retrouver sa disposition sur cette machine.

Un panneau est un emplacement : il porte la taille, le repère actif, l’agrandissement et le masquage. Un module est une vue : Arbre, Détail, Fichiers, Contrats, Ticket, Parcours, Git, Recette ou Diagramme. Ticket réunit Statistiques, Journal et Ticket ; le Parcours est un module à part. Sa lecture voyage avec lui. Flux et Ensemble sont deux modes d’Arbre ; Code et Passage sont deux représentations de Détail.

Commencer à lire

La disposition initiale présente Fichiers à gauche, Arbre en vue d’ensemble au centre, Détail à droite et Git dans l’emplacement inférieur. Les trois emplacements principaux et celui du bas peuvent tous recevoir un module. Tableau, Config et Harnais sont des pages globales ; les fermer rend l’espace laissé derrière elles.

Choisir, déplacer, échanger

Le choix en tête de chaque panneau liste les modules, avec la raison quand l’un ne peut pas être ouvert dans le contexte courant. Choisir un module déjà installé échange les deux contenus. Choisir un module rangé remplace le contenu de ce panneau ; la lecture remplacée reste disponible en choisissant de nouveau son module.

Ticket offre trois boutons de navigation entre ses sous-vues. Fichiers et Ticket peuvent se lire en bas ; Git peut prendre un panneau principal. Un clic rend le panneau actif, indiqué par son bord. Il ne change pas le symbole actuellement lu ni la cible d’endossement.

La frontière entre deux fenêtres se glisse à la souris. Un séparateur focalisé se règle aussi avec les flèches du clavier. Agrandir donne temporairement la place à un panneau ; le même geste ou Échap rend les tailles et les modules précédents. ↺ restaure la disposition initiale.

La disposition, les tailles et la visibilité se retiennent localement, par projet. Elles ne font pas partie du workspace partagé. Si une extension manque après rechargement, l’écran la nomme et permet de choisir une autre vue ou de restaurer la disposition. Un panneau qui montrait l’ancien module « Vue d’ensemble » montre l’Arbre (vide si l’Arbre est déjà ailleurs) ; une sous-vue Parcours de Ticket retenue rouvre Ticket.

Les touches ciblent la vue

Espace liste les commandes des modules installés : f Fichiers, a Arbre, d Diagramme, c Détail, g Git, t Ticket, p Parcours, k Contrats et r Recette. s ouvre la recherche : fichier (f), grep (g) ou usages (d). Dans Arbre, a f choisit Flux et a e Ensemble ; Diagramme, à côté de l’Arbre ou sans lui, suit la ligne qu’on y choisit (Le diagramme d’un flux). Dans Ticket, t s/j/t choisit Statistiques, Journal ou Ticket ; le Parcours se pilote dans sa vue. La lettre suivante choisit une option du module : Espace c p règle les plis du Code, même au centre ou en bas. Si Détail est rangé, c disparaît de ce premier niveau. Il reste disponible dans le choix d’un panneau. Aucune lettre répétée ne masque une vue. Inventaire n’est plus proposé dans les sélecteurs. Les lectures restent présentes tant que leurs modules sont installés ; un plein écran retire seulement les autres panneaux temporairement.

Une flèche désigne un panneau : ← gauche, ↑ centre, → droite, ↓ bas. Espace ↑ f installe Fichiers au centre ; Espace ↑ ↑ agrandit ou restaure le centre. Espace ↑ 0 cache ou révèle le contenu central, avec sa lecture conservée. La barre de commandes reste accessible : verticale pour les panneaux principaux repliés, horizontale pour celui du bas. Les quatre flèches sont réunies sur une seule ligne dans la boîte Espace. Espace 0 revient à la disposition initiale. Le rendu du Code se choisit avec Espace c s (unifié ou côte à côte). Quand son panneau est agrandi, Code passe automatiquement au côte à côte et au fichier entier. Le panneau transmet sa présentation ; Code porte cette adaptation. Restaurer retrouve la lecture compacte avec son rendu choisi et ses plis, sans mémoriser le choix automatique.

Depuis l’Arbre, les flèches parcourent les nœuds, Alt+↑/↓ font défiler le Code et 0, 1–4, ? gardent leur sens. Mettre le Code ailleurs n’ajoute aucun changement de focus à chaque nœud. Un Code hors écran garde son contenu, mais ces touches n’endossent aucune lecture invisible. Échap dépile l’interaction visible avant de quitter la lecture ; il ne masque pas un panneau simplement parce qu’il est actif.

Fichiers : Projet et Ce ticket

Un seul module offre les deux périmètres. Projet explore tous les repos, recherche un fichier par nom et lit aussi les fichiers du disque sans feature. Ce ticket, où s’ouvre une feature, range les fichiers touchés, avec leurs symboles, ronds, fils et comptes de relecture. Changer de périmètre ne change pas l’identité actuellement lue et ne transforme pas un fichier du disque en symbole endossable.

Ajouter une vue locale

Le guide contributeur vit dans web/extensions-locales/README.md et l’exemple technique dans fixtures/modules/temoin.ts. Cet exemple n’est pas une vue proposée dans l’application. Une extension est chargée à la construction de l’interface, depuis son dossier local, et déclarée par son propre descripteur. Elle reçoit feature et sélection et demande ses synergies au contrat commun.

Composer pour une question précise

La première disposition suffit pour commencer. Composer devient utile lorsque deux représentations répondent ensemble à ta question. Par exemple, tu veux confronter une étape du Parcours à la spec du Ticket : installe Ticket dans le panneau inférieur (Espace ↓ t), le Parcours à gauche (Espace ← p). Une étape cliquée dans le Parcours continue à viser l’Arbre ; elle ne cherche pas le panneau du centre. Tu peux ensuite échanger Code et Arbre si le fichier demande davantage de largeur. Les panneaux portent les dimensions, donc l’échange transporte les lectures sans échanger leurs tailles.

Autre exemple : tu relis le travail fichier par fichier tout en gardant les flux à portée de vue. Installe Fichiers dans le panneau gauche : il s’ouvre sur Ce ticket. L’Arbre reste dans son panneau. Cliquer un symbole dans Fichiers ouvre la même identité que cliquer son occurrence dans l’Arbre. La note de criticité porte sur cette identité, pas sur la liste qui a permis de la trouver. Le compte de relecture reste commun aux deux représentations.

Ces compositions sont des possibilités, pas un ordre de lecture. La disposition peut être plus pratique pour une question et moins pour la suivante. Tu peux la restaurer sans effacer ce que tu as déjà endossé : l’organisation des vues est une préférence locale, la lecture est un fait de la feature. Ne confonds pas non plus le retour à la disposition initiale avec une navigation arrière. Le premier range les modules ; la seconde revient à un contenu précédemment consulté.

Parcourir, lire, endosser : une séquence

Commence par ouvrir une feature, puis choisis la représentation par flux dans l’Arbre. Clique une ligne : elle est sélectionnée et le Code montre son symbole. Le panneau de l’Arbre reste actif. Utilise les flèches pour poursuivre la lecture ; Alt+↓ fait défiler le Code sans quitter cet Arbre. Quand le symbole est endossable, 0 le marque relu sans note. Les chiffres ajoutent ton jugement ; ? dit que tu n’as pas compris. Les règles sont celles de Relire et endosser.

Maintenant échange les modules Code et Arbre par le choix du panneau central. Le Code est au centre et l’Arbre à droite. Clique une ligne de l’Arbre : la même séquence reprend depuis ce panneau. Il n’est pas nécessaire de cliquer le Code avant chaque endossement. Le focus est celui du geste, alors que la cible de la lecture est le symbole ouvert. Ce sont deux faits distincts.

Si un autre panneau prend le plein écran, les chiffres ne partent plus sur le Code invisible. Restaurer retrouve la lecture ; cliquer un autre nœud la remplace et révèle le panneau. Un fichier ouvert depuis Projet peut être absent du diff ou ne correspondre à aucun symbole endossable. Dans ce cas, l’ancien symbole ne reste pas la cible des chiffres. Voir la source n’est pas automatiquement avoir quelque chose à endosser.

Panneau actif et contrôles ordinaires

Le bord actif repère le panneau où tu agis. Les commandes de composition désignent explicitement le panneau avec une flèche ; elles ne dépendent pas du dernier panneau activé. Les commandes nommées, comme afficher Code ou plier l’Arbre, continuent à viser leur module. Elles ne deviennent pas des commandes du dernier panneau cliqué. Tu peux donc composer au clavier sans réapprendre les gestes de lecture chaque fois qu’une vue change de place.

Un champ reste un champ : les lettres y saisissent le texte, les flèches y gardent leur fonction habituelle, et Espace n’ouvre pas la boîte des raccourcis. Sur un bouton focalisé, Espace ouvre l’aide ; Entrée active le bouton. Le choix de module utilise les contrôles du navigateur ; tu peux y parcourir les options puis confirmer. Quitte le contrôle pour reprendre les accords de l’application. L’actualisation d’un compteur ou l’arrivée d’une source dans un autre panneau ne lui transfère pas le focus.

Le même principe vaut pour les fenêtres de recherche et les discussions. Une boîte ouverte reste l’interaction en cours. Les commandes des modules ne doivent pas agir derrière elle. Cette règle empêche notamment une note de partir alors que tu réponds dans un fil. Les possibilités d’une commande sont dites dans la boîte des raccourcis ; relire la raison est plus utile que répéter une touche qui vient d’être refusée.

Installer, ranger, agrandir

Installer donne un panneau à un module. Ranger arrive lorsque tu choisis une autre vue à sa place : le module n’occupe plus d’emplacement. Agrandir donne temporairement l’espace à un panneau et retire les autres de l’affichage. Ces états n’ont pas la même conséquence lorsqu’une navigation demande à retrouver une vue.

Un module installé a une place. Un module rangé n’en a plus. Utilise le sélecteur ou Espace, une flèche, puis sa lettre. Sur un panneau occupé, ce choix range son contenu ; ce n’est pas un échange, puisque le module demandé n’avait pas de place de départ. À l’inverse, choisir une vue déjà installée dans le choix d’un panneau échange les deux modules.

L’agrandissement est temporaire. Agrandir le Code met les autres panneaux hors écran ; restaurer rend leur visibilité précédente aux modules installés. Cacher un panneau par Espace, flèche, 0 conserve son contenu et sa barre de commandes ; répéter le même accord le révèle à sa taille précédente. Choisir son module dans la barre le révèle aussi. Le rendu côte à côte change uniquement la présentation du Code ; le plein écran reste un geste du panneau. L’organisation et les tailles ordinaires sont mémorisés ; l’agrandissement sert l’interaction du moment. Il ne devient pas une nouvelle disposition obligatoire à la prochaine ouverture.

Échap suit ce que tu es en train de faire

La pile de gestes garde le sens de la lecture. Une boîte de raccourcis se ferme avant le Code. Un choix ouvert dans un fil se referme sans poster. Une sélection qui allume les occurrences s’éteint avant la navigation. Les loupes, l’isolement d’un flux et les agrandissements se défont avant de quitter le contenu.

Lorsque rien de prioritaire n’est ouvert, Échap quitte la lecture issue de la navigation. Il ne dit pas « fermer le panneau actif ». Sinon, cliquer Ticket pour relire la spec changerait le sens d’Échap, et déplacer Code changerait encore ce sens. Le plein écran se commande explicitement par deux mêmes flèches ou le bouton Agrandir. Le comportement du retour historique est décrit dans Le Code, celui des accords dans Le clavier.

Pour comprendre un Échap qui ne quitte pas immédiatement le Code, regarde ce qui vient de changer : une surbrillance est-elle tombée, une loupe a-t-elle été retirée, un rendu côte à côte est-il revenu à l’unifié ? Il n’est pas nécessaire de recomposer l’écran après chaque dépilement. Les modules continuent de représenter les mêmes identités, à leurs places actuelles.

Les pouvoirs des modules

Les modules coopèrent par des capacités déclarées. Un geste ponctuel demande une action à son destinataire : Arbre ouvre la sélection dans Détail ; Statistiques, dans Ticket, filtre les nœuds d’Arbre ; Parcours y isole une entrée. Ces gestes retrouvent le module installé, quelle que soit sa place. Un destinataire rangé n’est pas installé automatiquement : si le Parcours n’est nulle part, un fil d’étape cliqué au Journal le dit (« Le Parcours n’est dans aucun panneau : Espace + une flèche + p l’installe. »).

Un pouvoir de lecture fournit au contraire des faits tant que son module est installé. Recette est le fournisseur de la lecture d’exécution. Arbre et Fichiers montrent les nœuds traversés ; Détail montre les passages de la sélection. Le module Recette indique les vues installées qu’il influence. Un seul fournisseur est accepté pour chaque pouvoir : il n’y a pas de priorité cachée entre deux modules concurrents.

Ticket et Recette peuvent cohabiter. Ticket conserve Statistiques, Journal et Ticket. Ses filtres continuent à agir sur Arbre, y compris lorsqu’il représente une recette ; ils ne changent ni la recette choisie ni ses verdicts. Recette fournit les faits d’exécution, Ticket demande des navigations ou des filtres : chacun a un rôle lisible.

Le pied du Détail

Sous le dernier commit du fichier, le Code porte un pied du Harnais : ce que le Harnais a servi à ton IA pour ce nœud. Replié, il tient sur une ligne qui compte : « Harnais : 5 éléments — 1 suivi ou écarté par l’IA · 3 attendent un regard ». Un clic le déplie, et ce choix reste d’un nœud à l’autre. Il arrive après le code, et se lit pareil en unifié et en côte à côte.

Chaque élément est cité tel quel, avec sa famille (icône et nom), son état dit par sa cause, et un lien vers sa source : une consigne ouvre la page Harnais, un précédent ou une décision son fil, un critère l’onglet Ticket de sa feature. Une source qui ne s’ouvre plus le dit, sans lien. Trois niveaux, en mots, du plus fort au plus faible :

  • suivi ou écarté par l’IA : cité dans un fil de ce nœud, ou écarté, avec sa raison ;
  • servi avant que ces lignes s’écrivent : une session l’a reçu, puis a écrit des lignes de ce nœud — retrouvées même déplacées, jamais « la plus proche » ;
  • servi dans ce fichier pendant la session : les lignes écrites sont inconnues (un geste de terminal, un client sans hook : « non garanti »).

Suit ce qui s’applique ici sans que personne l’ait vu servir. Chaque service dit sa date, son canal (le hook, l’ouverture de session, le prologue d’un skill, la lecture à la demande) et son moment — « moment inconnu » quand le canal ne le dit pas. Ce qu’a fait l’IA n’y est dit que si elle l’a dit : « ni cité ni écarté » reste « Atlas ne sait pas ».

Tes gestes sont ceux de l’élément. Une consigne a Confirmer et Invalider…, comme sur la page Harnais : l’invalidation écrit sa raison. Un précédent a un verdict à ce nœud : invalidé, il n’y est plus servi à ton IA — un autre prend sa place, et lui reste servi ailleurs ; confirmé, il passe devant tous les autres ; « Lever mon verdict » le retire. Deux personnes qui le jugent sont nommées, la plus récente décide. Un critère, un cas ou une décision n’ont pas de bouton : le pied dit où ils se corrigent. Seul un clic humain pose un verdict, aucun outil de l’IA.

Trois états, jamais « aucun » sur une ignorance : des éléments ; « rien du Harnais à cet endroit » ; « pas pu lire » avec sa raison. Un fichier ouvert hors d’un nœud (● Local, explorateur) montre ses éléments et dit que les précédents servis ne se lisent que sur un nœud.

Git et Recette

Git contient toujours Local, Branches & repos et Revue. Son déplacement n’est pas un changement de mode. Le repo sélectionné et la lecture en cours restent les siens. Les faits de Local sont aussi ceux dont Fichiers et Relecture se servent ; composer l’espace n’ajoute pas un second inventaire du disque. Une activité liée à l’affichage se suspend lorsque son panneau est hors écran ou lorsque l’espace passe derrière une page.

Installer Recette active sa coopération dans la disposition que tu as choisie. Aucun autre module ne change de panneau. Recette contient les critères, le protocole, la Non-régression et les Captures, sous des choix internes. Le choix de recette et sa fraîcheur vivent dans ce module. Détail montre le Passage du nœud sélectionné — événements, échanges ou médias — à la place du Code. Feature, recette choisie et sélection sont communes ; les vues ne se commandent pas par leurs emplacements et n’importent pas le fonctionnement interne des autres modules.

Ces modules restent déplaçables pendant la recette. Espace r a ouvre Protocole. Remplacer Recette par un autre module rend la lecture normale de Code, Fichiers et Arbre, sur la même sélection. Cacher ou agrandir un panneau ne retire pas son module : le pouvoir de Recette reste actif. Les boutons code / recette du header ont disparu ; la présence du fournisseur suffit à déterminer la lecture. Les touches d’endossement du code ne deviennent pas des validations de recette. Les règles de la recette et de ses preuves sont décrites dans La recette.

Retrouver un espace utilisable

Une disposition appartient à cette machine et à ce projet. Recharger la page retrouve les modules, tailles et visibilités enregistrées. Changer de feature conserve l’organisation du projet, mais les contenus deviennent ceux de la feature courante. Une source arrivée en retard pour un contenu quitté ne doit pas être présentée comme la lecture suivante. Le panneau est un hôte ; il n’est pas un moyen de garder deux features concurrentes sous un même header.

Si une vue locale a été retirée, son identifiant peut rester dans les préférences. Atlas le nomme et laisse choisir une autre vue. Une préférence ancienne ou illisible revient à une disposition utilisable. Le bouton ↺ est aussi un point de reprise quand tu as perdu le fil de tes échanges. Les fichiers du projet, le Ticket et les endossements ne sont pas réécrits pour corriger la disposition.

Pour comparer deux organisations, garde une question et une feature identiques. Compte les gestes pour trouver un nœud, lire sa source, endosser, suivre un critère et retrouver un fil. Sépare les gestes uniques de composition de ceux qui se répètent à chaque nœud. Le résultat utile est ce que tu observes sur ce parcours précis : une autre disposition n’est pas présumée meilleure parce qu’elle offre davantage de choix.

Ce qu’Atlas ne fait pas

Ce premier espace propose quatre emplacements et une instance de chaque module. Il ne découpe pas arbitrairement l’écran, ne multiplie pas une même vue et ne transforme pas Code en éditeur ou en terminal. Les pages Tableau, Config et Harnais restent globales. Les règles de flux, de ricochet, d’endossement et de recette restent celles décrites dans leurs pages.

Les extensions sont locales à la construction de l’interface. Cette ouverture ne constitue pas un catalogue ni une publication de vues. La disposition personnelle n’est pas une donnée partagée du workspace et ne devient pas une consigne pour les autres relecteurs. Elle sert à organiser ton espace ; elle ne dit pas à leur place ce qu’ils doivent avoir lu ou compris.
