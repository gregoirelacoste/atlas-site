Amorcer le Harnais

Retrouve les savoirs de ton projet dans son histoire, conserve leurs preuves et reprends la lecture par lots, sans activer de consigne à ta place.

Retrouve les savoirs de ton projet dans son histoire, conserve leurs preuves et reprends la lecture par lots, sans activer de consigne à ta place.

L’amorçage constitue un premier Harnais, le savoir que ton projet rend consultable à l’IA, depuis les commits, la documentation et les commentaires de code. Le skill atlas:amorcer-harnais interprète ces sources avec le modèle de ta session. Atlas lit les versions Git, vérifie les citations et conserve les résultats. Il n’appelle aucun modèle depuis son serveur.

Tu peux commencer sans ticket, sans conversation de review et sans consigne préexistante. Une piste historique est un élément extrait de ces sources, avec sa formulation, son explication et ses preuves. Elle devient consultable après son dépôt, sans attendre une validation individuelle de tout le corpus. Elle n’est pas une consigne, une instruction active du projet, par le seul fait de son import.

Lancer le skill depuis ton projet

Ouvre ta session IA sous le dossier du projet, avec le plugin Atlas à jour (Brancher l’IA). Dans Claude Code, lance :

/atlas:amorcer-harnais

Dans un autre client, demande atlas:amorcer-harnais par son nom. Le skill se lance sur demande explicite, de toi ou d’un agent que tu as lancé. Il n’est pas un moment, une étape signée de la vie d’une feature : aucun passage ne se coche dans Relecture.

Tu peux joindre directement les précisions : dépôt projet-api, référence main, chemins à lire, chemins à exclure et budget. Le skill demande celles qui manquent. Il commence par lire l’état d’Atlas : identité du projet, dépôts membres, bornes et passes déjà conservées. Une instance qui ne se lit pas ou répond pour un autre projet l’arrête. Il ne complète pas depuis un autre projet.

L’accueil d’Atlas porte une invitation à lancer ce skill. Cliquer cette invitation ouvre le Harnais ; cela ne lance pas l’IA. Clique ensuite Amorçage historique, en tête de la page Harnais. Cet espace explique le skill et montre ses résultats. Le lancement et la conduite de la lecture restent dans ta session de code.

Fixer les références et les chemins

Une passe d’amorçage est une lecture dont les dépôts, références, chemins et bornes sont conservés ensemble. T0 est le commit fixé pour chaque dépôt. Une branche ou un tag est résolu une fois en commit : si la branche avance ensuite, la passe garde ce commit. Plusieurs dépôts peuvent avoir des T0 différents.

tu précises comment le choisir
les dépôts un à trente noms de repos membres du projet ; chacun une seule fois
la référence de chaque dépôt une branche, un tag ou un commit disponible localement dans Git
les chemins inclus des préfixes relatifs au dépôt, ou la chaîne vide pour tout inclure
les chemins exclus des préfixes relatifs à retirer des chemins inclus ; une liste vide est valable
les bornes celles annoncées par Atlas, ou des valeurs explicites pour cette passe

Les chemins sont des préfixes, pas des globs. src vise ce chemin et ses descendants, pas src2 ; src/**/*.ts ne demande pas tous les fichiers TypeScript. Dans les arguments de l’outil, inclus: [""] signifie tout le dépôt. Les chemins absolus, la remontée .., .git et .atlas-workspace ne sont pas des chemins de corpus acceptés.

Les inclusions et exclusions bornent les fichiers de documentation, les commentaires et les chemins du diff. Les messages de commit restent complets : les exclure par chemin n’est pas un filtre proposé. Le corpus suit l’ascendance Git de T0, pas les seules dates. Un commit ancien sur une branche jamais réunie à T0 n’y entre pas. Un commit futur n’y entre pas non plus.

La première passe énumère les messages, les diffs par parent et les versions de documents ou de commentaires touchées par les commits retenus. Elle ajoute aussi les documents et commentaires présents à T0, même inchangés dans ces commits. Pour un merge, chaque parent a son diff. Le skill doit lire message et diff avant de raconter ce qu’un correctif a fait.

Atlas ne sort aucune branche et ne lance aucun script du projet. Il ne récupère pas de nouvel historique distant pendant cette lecture. Si ton clone est incomplet, la passe le dit : les sources accessibles peuvent être lues, mais les ancêtres manquants restent inconnus.

Borner la lecture et son coût

Avant l’extraction, le skill annonce les bornes. Après fixation de T0, il rend les références résolues, les sources énumérées, les exclusions et les limites. Lis ce premier bilan : une borne atteinte n’est pas une absence de savoir dans le projet.

borne de l’outil défaut ce qu’elle borne
commits 1 000 les commits retenus par dépôt ; au-delà, les plus anciens ne sont pas parcourus
fichiers 3 000 les versions de fichiers énumérées dans l’ensemble de la passe
octetsSource 262 144 la lecture entière d’une source
octetsLot 98 304 le texte total d’un lot
sourcesLot 12 les sources tentées dans un lot

Chaque borne accepte un entier positif, jusqu’à cinq fois son défaut. Elles se règlent à la fixation d’une passe, pas au milieu d’un lot. Une source entière qui dépasse le budget d’un lot est signalée et exclue ; elle n’est pas découpée pour faire croire à une lecture complète. Une source illisible ou dépassant la borne de lecture garde aussi sa raison.

Un lot historique est la portion lue puis déposée avant de passer à la suivante. Il rend les textes, leurs lieux et leurs empreintes, les limites, le nombre de sources restantes, les octets lus et le temps de lecture. Les sources tentées et les sources effectivement lues ne sont donc pas toujours aussi nombreuses. Un lot peut ne produire aucune piste utile : déposer zéro proposition est valable et fait avancer la passe.

Les limites de Git et les exclusions de fichiers ne mesurent pas les tokens facturés par ton modèle. Le nombre d’appels, le volume et le temps de lecture décrivent le coût de construction ; les lectures et l’interprétation de ta session ajoutent leur propre coût. Garde ces coûts distincts de la taille des réponses obtenues ensuite par la recherche.

Comprendre ce qui est extrait

Le skill classe selon la matière disponible dans les six familles du Harnais. Une famille sans source reste vide.

famille matière historique
Règle contrainte écrite
Engagement promesse explicite
Garde vérification décrite
Méthode procédure
Mémoire épisode, correctif ou retour arrière
Contexte explication technique ou métier

La famille indique ce que la piste raconte, pas son autorité actuelle. Une Règle importée reste une piste. Un Engagement ne fabrique aucun ancien critère de ticket ; une Méthode ne déclare aucun skill du projet.

Chaque proposition distingue trois formes de preuve :

valeur conservée ce qu’elle affirme
explicite la source écrit la contrainte, la promesse ou la raison
observation le changement est visible dans le diff
inference l’IA interprète ce qu’elle a lu

Un test ajouté ne prouve ni qu’il a tourné ni qu’il échouait avant. Un diff peut montrer le retrait d’une vérification sans en expliquer la raison. L’explication absente reste inconnue. La formulation et l’explication de l’IA restent séparées des citations : une reformulation ne se lit pas entre guillemets comme si la source l’avait écrite.

Atlas accepte les citations seulement si elles reprennent des lignes entières exactes des sources lues. Une citation inventée ou tronquée est refusée. Une proposition peut citer les lots antérieurs de la passe et des passes précédentes reliées ; elle cite toujours au moins une source du lot qu’elle dépose. Une preuve héritée reste soumise à la passe courante : dépôt encore inclus, commit — et parent pour un diff — dans l’ascendance de son T0, chemin dans ses inclusions et hors de ses exclusions. Si l’ascendance ne peut pas être prouvée, le dépôt de la proposition est refusé. Si les chemins inclus ou exclus changent, un ancien diff doit être relu dans la nouvelle passe avant d’être cité : son ancien filtrage ne vaut pas pour ce nouveau périmètre.

Le modèle déclaré dans la provenance est celui indiqué par la session, pas une attestation d’Atlas sur le fournisseur réellement utilisé.

Les épisodes peuvent relier plusieurs commits, un retour arrière ou un déplacement. Chaque lien porte sa justification, ses preuves et son état, établi ou ambigu. Un même chemin ou un texte presque identique ne prouve pas qu’il s’agit du même épisode. Une annonce, une contradiction et un remplacement établi restent distingués. Leurs liens n’activent ni ne retirent une consigne.

Un lieu historique accepte seulement un fichier ou un dossier prouvé par une version de fichier effectivement citée. Pour fichier projet-api/docs/migrations.md, cite une version de ce fichier ; pour dossier projet-api/docs, cite une version d’un fichier qu’il contient. Un document qui mentionne src/migrations/retour.ts ne prouve pas l’existence de ce fichier. Les lieux de type symbole ou contrat sont refusés, même si leur nom apparaît dans une citation. Conserve alors le fichier réellement prouvé, ou endroits: [], en annonçant la limite dans limites.

L’applicabilité reste séparée du lieu : choisis historique ou indeterminee. actuelle-etablie est refusé à l’import : le corpus historique ne prouve pas l’applicabilité actuelle. Un nom de fichier qui existe encore ne prouve pas que la règle s’applique aujourd’hui. Une suppression du lieu n’efface pas le souvenir conservé ; l’activation humaine choisit son lieu actuel.

Reprendre une passe interrompue

Dans Harnais → Amorçage historique, clique Actualiser les passes, puis déplie une ligne de Passes et reprises. Elle donne l’identifiant de passe, les sources parcourues, les lots déposés, les bornes, les mesures, les exclusions, les restants et les inconnus. Donne cet identifiant au skill en lui demandant explicitement de reprendre cette passe.

La reprise repart après le dernier dépôt durable, pas après le dernier texte que l’IA avait commencé à lire. Un lot lu mais non déposé est rendu identique. Si le dépôt avait réussi avant l’interruption, rejouer exactement le même contenu ne duplique pas les éléments. Le dépôt d’un contenu différent sous le même lot est refusé : il faut une nouvelle révision, pas réécrire l’ancien lot.

Une passe relancée avec les mêmes paramètres et les mêmes commits résolus retrouve son suivi. Pour réinterpréter un corpus, demande une nouvelle passe reliée à la précédente, même si T0 ne bouge pas. Une proposition identique — clé de continuité, portée, lieux, citations Git et interprétation — conserve son identité et sa version : elle ne redevient pas neuve parce qu’elle traverse une autre passe.

Une interprétation modifiée produit une version distincte. Une portée ou des lieux différents peuvent distinguer l’identité elle-même. Les gestes humains d’une version ne passent pas silencieusement à une autre. Ainsi, rejouer une proposition mise de côté ne la rétablit pas ; une nouvelle interprétation reste visible comme nouvelle version, avec ses propres gestes.

Actualiser à T1

T1 est la nouvelle référence choisie lors d’une actualisation. Relance le skill en donnant l’identifiant de la passe précédente et les nouvelles références. Il fixe une nouvelle passe, liée à l’ancienne, et Atlas vérifie l’ascendance dépôt par dépôt.

situation lecture effectuée
T0 est ancêtre de T1 et les chemins sont identiques nouveaux commits et versions de fichiers affectées
les chemins changent nouvelle lecture complète, dans les bornes choisies
la référence reste identique réinterprétation du corpus dans une révision distincte
l’ascendance est perdue ou réécrite avertissement et révision complète bornée

Les preuves de T0 restent conservées. Le skill peut les rouvrir pour relier un épisode aux nouveaux commits, mais leur réutilisation dans une proposition exige leur admissibilité dans la nouvelle passe. Demande un bilan des ajouts, nouvelles interprétations, contradictions et limites. Une histoire réécrite ou inaccessible ne veut jamais dire « aucun changement ». Les sources anciennes ne sont pas complétées silencieusement par la documentation actuelle.

Consulter les preuves et agir

Dans Pistes importées · toutes les versions, choisis une version. La liste avance par groupes de quarante, avec Versions précédentes et Versions suivantes. La fiche donne formulation, explication, famille, preuve, portée, applicabilité, lieux historiques, date d’import, extraction, liens, limites et gestes humains. La date des sources se lit séparément, sur leurs boutons.

Clique Ouvrir la preuve · lignes …, ou un bouton portant dépôt, commit et source. Preuve à sa version exacte montre le texte conservé et son intégrité ; Atlas essaie aussi de le relire au commit annoncé. Si ce commit ou le dépôt n’est plus accessible, la fiche le dit et garde l’extrait importé. Elle ne le remplace pas par celui du checkout actuel.

La recherche commune retrouve les pistes avec les mots du problème, sans fichier ni feature. Un résultat historique porte Ouvrir les preuves historiques et les gestes humains : ce bouton rejoint la version concernée. La recherche ordinaire propose la dernière version de chaque identité ; l’espace d’amorçage garde toutes les versions. Une question ne relance ni parcours Git historique ni interprétation IA.

ton geste ce qu’il change
écrire une raison puis Mettre cette version de côté retire cette version des pistes proposées par la recherche ; conserve texte, preuves et raison
juger un rapprochement dans la recherche juge ce résultat pour un problème, sans mettre sa source de côté
Activer comme consigne · geste humain ouvre le choix explicite pour une Règle, une Garde ou un Contexte

La mise de côté et l’activation exigent ton identité Git ; la raison est conservée sur cette version.

Pour activer, relis le contenu montré, écris ta raison et le lieu actuel : fichier projet-api/src/migrations/retour.ts, dossier projet-api/src/migrations, ou tronc commun. Le premier désigne un fichier exact ; le deuxième, un dossier. Coche J’active explicitement ce contenu au lieu saisi., puis clique Activer cette consigne.

Atlas crée une consigne de code adoptée par l’humain, avec l’explication, ta raison et la provenance historique. Règle devient une instruction à faire, Garde une vérification, Contexte une explication. Le lieu saisi exprime ton choix actuel ; les anciens lieux ne le choisissent pas pour toi. La consigne suit ensuite la vie ordinaire des consignes.

L’activation applique aussi leur format : notamment une phrase de 120 caractères au plus. Une piste plus longue ne devient pas automatiquement une consigne raccourcie. Engagement, Méthode et Mémoire restent consultables et peuvent être mis de côté. Une version déjà mise de côté ne peut pas être activée ; aucun bouton ne défait cette mise de côté. Mettre la piste de côté après son activation n’invalide pas la consigne créée : celle-ci garde ses propres gestes.

Si l’activation reste à reprendre

Avant de créer la consigne, Atlas enregistre durablement ton intention : auteur, lieu, raison et date d’origine. Elle reste visible sous activationEnCours jusqu’à la fin du transfert et de son indexation. Un incident après cet enregistrement peut donc laisser une consigne déjà active, même si la confirmation finale manque.

La fiche affiche alors Activation à reprendre. Le retour du geste précise consigne déjà active si la création a été confirmée, ou issue du transfert à vérifier si elle reste inconnue. La réponse HTTP 202 porte activation.etat: "a-reprendre" et sa raison ; elle ne signifie pas que l’activation a été refusée. L’état terminé porte activation.etat: "terminee".

Redémarre le serveur Atlas pour reprendre automatiquement le transfert, ou renvoie le même geste sur la même version, avec l’auteur, le lieu et la raison d’origine. Dans la fiche, recopie ces valeurs conservées, coche à nouveau la confirmation et clique Activer cette consigne. Changer ces valeurs pendant la reprise est refusé. La reprise conserve le geste humain et son adoption sans les dupliquer ; elle retire activationEnCours quand le transfert et l’indexation sont terminés. Mettre la version de côté est refusé tant que cette activation reste en cours.

Lire le bilan sans inventer un gain

Le bilan du skill doit rendre le projet, les commits fixés, le périmètre effectivement lu, exclu, restant ou inconnu, les octets, sources et temps de lecture. Il donne les familles alimentées, y compris vides, les ajouts, les nouvelles interprétations et les contradictions. Les comptes de la page permettent de revenir aux passes ; ils ne notent pas la qualité du savoir.

La fidélité des pistes, leur utilité pour un humain, les faux amis, les abstentions et les besoins entièrement couverts exigent un jugement humain. Le rejeu comparatif dispose d’un protocole technique, mais aucun panel humain réel ne démontre actuellement un gain. Les coûts de construction et de consultation se lisent séparément ; produire davantage de pistes ne prouve pas que les bonnes contraintes arrivent.

Ce qu’Atlas ne fait pas

  • Il n’importe pas Jira, les discussions de merge request, une messagerie ou une décision orale. Une information absente des commits, documents et commentaires reste inconnue.
  • L’import n’active aucune consigne, même dans Règle ; il refuse une applicabilité déclarée actuelle. Il n’ajoute aucune instruction au hook ou au tronc commun.
  • Il ne réécrit pas les projets analysés, n’exécute pas leurs scripts et ne fabrique aucun ancien ticket, conversation, service à l’IA ou jugement humain.
  • Les sources ne commandent pas le skill : une instruction trouvée dans un document ou un commit reste du contenu du corpus, pas une action à exécuter.

Limites connues

La documentation est reconnue par les extensions .md, .mdx, .rst, .txt et .adoc. Les commentaires sont lus lexicalement dans les fichiers TypeScript, JavaScript, Java, Kotlin, Swift, C, C++, CSS, Go et Rust reconnus par leur extension. Seuls // et /* … */ sont lus, avec les lignes originales conservées et les chaînes retirées. Les syntaxes imbriquées et les regex ne sont pas garanties ; les autres syntaxes ou extensions ne sont pas lues comme commentaires. Le diff d’un fichier peut néanmoins appartenir au corpus : cela ne prouve pas que ses commentaires ont été reconnus séparément.

Les citations vérifiées et les lieux prouvés ne certifient pas toutes les conclusions du modèle ni l’applicabilité actuelle : relis les preuves avant de choisir un lieu actuel. Un historique incomplet, un binaire, une lecture refusée ou une source trop grosse conserve sa limite. Une passe bornée ne promet jamais d’avoir lu toute l’histoire. Les preuves et les pistes restent consultables ; leur utilité générale et un gain de qualité restent non établis.
