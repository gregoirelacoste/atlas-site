Le Code

Le panneau de droite : le code réel du nœud que tu regardes dans l'Arbre — relu à chaque clic, jamais une copie — avec ses liens, ses fils de conversation et ce que tu en as déjà relu.

Le panneau de droite : le code réel du nœud que tu regardes dans l’Arbre — relu à chaque clic, jamais une copie — avec ses liens, ses fils de conversation et ce que tu en as déjà relu.

Il s’ouvre avec ce que tu ouvres

L’Arbre (détaillé dans L’Arbre) découpe le diff d’une feature en nœuds : une méthode, un fichier, un contrat (une surface dont d’autres dépendent). Sélectionne un nœud, et le Code affiche sa source réelle, lue dans git au moment du clic.

Tant que rien n’y est ouvert, Détail garde son panneau vide. Un nœud cliqué ou choisi aux flèches, un lien, un fichier ouvert par son nom ou un fil y ouvre le Code. Sa largeur est celle de son panneau : glisse sa frontière pour la régler. Échap quitte la lecture et le nœud tombe avec : 0, 1-4 et ? n’agissent que sur ce qui est ouvert. Le panneau garde sa place. Installer Recette remplace le Code par les passages d’exécution dans ce même Détail.

L’en-tête tient en deux lignes, et reste en haut

La première dit ce que tu lis : ←, la pastille (un c à l’encre contrat sur un contrat), le nom, sa signature (rien sur un fichier). À droite, l’état en une marque — un point (vert commité, gris codé, creux contexte, tirets prévu), modifié +12 −3, codé +4, non modifié ou prévu, puis · à revoir quand le code a changé depuis ta validation (relu, à relire : infobulle) — et, sur un symbole, ↑ usages. Une signature qui ne tient pas là passe en tête de la seconde ligne.

La seconde dit d’où ça vient, et ce qu’on en sait.

Élément Ce qu’il montre
dépôt/…/fichier.ts:184 le dépôt, le fichier, la ligne — jamais coupés
⇄ comparé à master le diff ne part pas de la base déclarée du projet (section suivante)
⇄ sur le disque, comparé au dernier commit ouvert sans feature, ou depuis ● Local : le non-commité, sans fils ; puis la branche (ou HEAD détaché), qui ne cède jamais
· FactureService la classe du symbole
▶ POST …/orders/create l’étiquette entière d’un point d’entrée ou d’un appel réseau (plus bas)
neuf aucune ligne de ce code n’existait à la base
Atlas propose 4 — migre la base la criticité proposée par la carte
criticité · toi 3 · alice 4 les notes posées en endossant, nommées
? pas compris · toi · carol qui a dit ne pas comprendre ce code
relu aussi · alice qui d’autre l’a endossé (atténué : avant un changement du code)
atteint par 3 tests via Facture.total ▾ un clic déplie les phrases des tests au-dessus du code
preuve : migration SQL ce qui a classé un contrat ou une frontière

Le chemin garde le dépôt et le nom du fichier entiers (l’entier en info-bulle) ; en côte à côte, il s’écrit en entier, dossiers compris. Trop long, il passe à la ligne entre deux dossiers. À l’étroit cèdent, dans l’ordre : la classe, les faits (sous un … qui les montre), enfin la signature par mots entiers. Un nom ne se coupe jamais. Le dernier commit du fichier — hash, sujet, scope — est au pied du code.

En dessous, ce que l’IA a compris : Ce que ça fait : (et Ce que ça faisait : au-dessus), sinon Pourquoi :, et Dit par l'IA : ; un ~ dit que c’est antérieur au dernier changement du fichier. Puis les fils du symbole, puis le code ; à l’ouverture, cet avant s’il tient dans la moitié haute du panneau, sinon le code d’abord.

Les types de la signature

La signature porte les mêmes encres que dans l’Arbre (Ce qui dépend de quoi) : bleu sur un type que ce nœud prend, orange sur celui qu’il rend. Sans enveloppes du langage déclarées pour ce projet, elle reste en encre neutre : Atlas ne devine pas.

Sur un nœud-contrat, le titre nomme le contrat s’il est seul, sinon le fichier.

L’étiquette d’un endpoint

Dans l’Arbre, un point d’entrée HTTP ne porte que le verbe — ▶ PATCH — et un appel réseau vers un autre service, ⇄ GET : c’est ce qu’un décorateur prouve. L’étiquette entière, non cliquable, vit ici, en tête de la seconde ligne : ▶ POST …/orders/create · v2, ou ⇄ PATCH /*/objects/customers/*.

Elle apporte l’aveu, qui se survole : un …/ en tête dit que le préfixe global de montage n’est pas lu, un chemin complet qu’il est déclaré, un * un segment dynamique non résolu. Ce qui est écrit sans marque est prouvé. Le …/ est un manque de déclaration : seule la clé routePrefix le retire (Configurer un projet). La version (· v2) est à côté du chemin, jamais dedans.

Ouvrir un fichier, et à quoi le Code le compare

Deux recherches ouvrent un fichier ici : Espace s f le cherche par son nom, Espace s g cherche une chaîne dans le contenu des dépôts et l’ouvre à la ligne trouvée (Fichiers et Inventaire).

La première offre en plus la base de comparaison, l’autre bout du diff montré. Par défaut courante — la ligne de base déclarée du projet (Configurer un projet) ; sinon les lignes d’intégration qu’Atlas connaît — develop, master, main — moins la déclarée.

Le Code montre le diff de la branche courante contre cette base, et sa tête le dit (« ⇄ comparé à master ») : un diff pris d’un autre point ne se lit jamais comme celui de la feature. L’info-bulle donne le commit exact.

Ce choix ne change pas : le fichier lu (là où il a été listé : le travail en cours pour un dépôt de la feature, sa base pour les autres), les fils de la feature (la marge en ouvre toujours un), la base déclarée du projet (il ne se retient pas). Un nœud de l’Arbre, un lien, un résultat d’usages ou de la recherche de contenu comparent toujours à la base déclarée, sans chip ; un dépôt hors feature, sans branche courante, s’ouvre sans comparaison.

Ce qu’il affiche, et ce qui se replie

En unifié, le Code se lit comme dans un éditeur. Le nœud ouvert est déplié de sa signature à sa dernière ligne, et encadré : le cadre dit ce que tu endosses. Hors du cadre, le fond des lignes changées pâlit sans perdre sa couleur, sauf sur un nœud de contexte, déjà grisé. Tout autre bloc (fonction, méthode, méthode supprimée) naît replié sur sa première ligne, au niveau le plus haut ; le reste (imports, champs, documentation collée au nœud, ligne retirée seule) reste visible.

Un pli dit après son ⋯ les lignes modifiées qu’il cache (⋯ 3 modifiées), supprimées pour une méthode retirée (⋯ 12 supprimées). Sa première ligne garde sa couleur : la signature modifiée d’un voisin se voit, hors du cadre. Sa marge dit ce qu’il reste à y relire (relu, à relire, à revoir). Sur un nœud-fichier, seuls les corps des méthodes qui ont leur nœud se replient. Un fichier sans autre nœud (doc, feuille, ● Local) se lit autour de ses changements, suppressions comprises, le reste derrière ⋯ N lignes inchangées.

Le chevron de marge plie ou déplie un bloc, au clic ou par Entrée. Rouvrir le nœud rend ces plis d’office ; tes plis survivent au plein écran, et le côte à côte a les siens.

Espace c p plie tous les blocs, enfants compris — un pli partiel devient « tout plié » ; rejoué, il les déplie, dans le Code seul.

Rendu unifié et côte à côte

Par défaut, le Code empile les lignes façon GitLab : suppressions et ajouts l’un sous l’autre, une ligne réellement modifiée en place ressort en bleu — appariée à son ancienne version par son CONTENU, pas par sa position — jamais d’une méthode retirée en entier à une neuve d’un autre nom (un renommage au corps réécrit : rouge, puis vert). Les mots qui changent dans une paire sont soulignés.

Espace c s bascule en côte à côte : la base à gauche, le résultat à droite, le fichier entier, sans pli d’office — chaque colonne ne montre que ses lignes. Un ruban relie chaque changement à sa place en face : rouge un retrait, vert un ajout, bleu une modification, pâle hors du cadre comme ses lignes ; un côté vide se resserre en un trait, là où ses lignes manquent.

Les colonnes défilent ensemble, en face au tiers haut du Code ; un changement de tailles différentes y incline le ruban — la plus courte attend, puis elles restent décalées jusqu’à son passage. Une longue ligne passe à la ligne. Cadre du nœud et fils vivent dans chaque colonne ; un pli cache ses lignes des deux côtés. Les tests gardent leurs titres seuls. Rejoué, retour à l’unifié et à ses plis ; sans lecture ouverte, la boîte le dit.

En plein écran, Code choisit seul le côte à côte, fichier entier et tests compris ; restaurer rend le rendu choisi et les plis compacts, sans rien mémoriser.

Espace, flèche, 0 cache ou révèle le panneau du Code sans perdre sa lecture ; deux mêmes flèches l’agrandissent ou le restaurent. Voir les panneaux et les modules.

Le pied : ce que le Harnais a servi ici

Sous le dernier commit, une ligne replie ce que le Harnais a servi à ton IA pour ce nœud : un clic la déplie, et tu y confirmes ou invalides ce qu’elle a reçu, à ce nœud. Il arrive après le code, pareil en unifié et en côte à côte. Il est décrit dans Les panneaux et les modules.

Les liens dans le code

Certains mots du code sont des liens, fond coloré, aux couleurs de couche de l’Arbre. Deux familles :

  • les appels sortants de ce nœud, localisés exactement : customerService.update( lie cette occurrence, pas les autres .update( ; alias et callbacks compris ;
  • les types, DTO, enums et constantes déclarés par un contrat que ce nœud importe — en orange.

Un clic sur un lien-méthode sélectionne ce nœud dans l’Arbre : l’Arbre se déplie jusqu’à lui, ses appelants directs se soulignent en pointillé, et le Code affiche sa source. Un lien-contrat ou une constante ouvre directement sa source — un type n’a pas forcément de ligne à lui dans l’Arbre.

Le reste est inerte, même si un homonyme existe ailleurs ; un nom local masque la fonction du module. Les liens d’appel attendent une nouvelle carte si la source a changé ; le côté base ne reprend pas ceux de la feature.

Aller à la définition, les usages

Un clic — simple, ou Ctrl/⌘+clic — sur un lien saute à sa définition ; maintenir Ctrl (⌘ sur Mac) allume les liens. Un survol affiche les gestes possibles : « ⌃ clic → définition · ⌥ clic / Espace s d → usages » sur un lien, « ⌥ clic / Espace s d → usages » seul sur un appel que Atlas n’a pas su résoudre.

Les usages répondent à « où ce nom apparaît-il, ailleurs ? », pour n’importe quel symbole affiché. Trois portes : Espace s d (le nom sélectionné, sinon le symbole survolé, sinon celui de l’en-tête), le bouton ↑ usages, Alt+clic sur un mot. Une fenêtre s’ouvre : définition en tête, puis chaque usage à sa ligne, l’aperçu à droite. Ouvrir un usage pose aussi le curseur de l’Arbre sur la méthode qui l’utilise.

C’est une recherche textuelle du nom, son pied le dit : chaque occurrence reste à juger. Elle compte les résultats, les masqués par le filtre d’import et les coupures à 200. « Aucune occurrence » ne dit pas « personne ne s’en sert » ; une source illisible donne « recherche incomplète » et sa raison. Les résultats s’ouvrent là où ils ont été trouvés (branche, worktree ou base). Un alias lié cherche le nom de sa définition.

Tu en sors par Échap ou un clic dans le vide.

Les occurrences d’une sélection

Sélectionne à la souris un texte sur une ligne du Code : ses autres occurrences dans le fichier affiché s’allument en cyan vif (unifié ou côte à côte), et la tête dit « 3 occurrences dans ce fichier », la sélection et les lignes repliées comprises. C’est une égalité de texte, pas un lien : sensible à la casse, pas un mot entier. Rien pour plusieurs lignes ni moins de 2 caractères. La sélection reste copiable ; clic ailleurs, Échap ou un autre fichier éteignent.

Le curseur de l’Arbre suit le code ouvert

Ouvrir une source sans passer par une ligne de l’Arbre — un lien du Code, l’index des contrats, le volet Fichiers, une recherche, un résultat d’usages — déplace la sélection sur le nœud qui porte ce fichier. Tu lis un type dans un contrat, tu l’endosses sur place : 0, 1-4 et ? visent ce que tu as sous les yeux (Relire et endosser). Le fichier se marque dans le volet Fichiers : dossiers dépliés, ligne en gras.

Deux cas seulement font atterrir le curseur : l’identité exacte du symbole ouvert, ou, à défaut, le nœud au grain fichier du même fichier, qui reçoit alors ton endossement. Jamais un nœud qui « ressemble ». Quand aucun nœud ne porte le fichier — un fichier hors flux, un fichier lu depuis le panneau Git — le curseur se retire : aucune ligne allumée, et le geste d’endossement ne part pas.

Revenir et ravancer

Alt+← rouvre la vue consultée avant, Alt+→ celle d’après — nœud, fichier ou fichier du ● Local. Ouvrir une vue neuve après un retour efface l’« après ». L’historique tient 50 vues par feature, se garde sur cette machine et survit au rechargement ; une vue dont le nœud n’est plus dans la carte est sautée, et la boîte des touches le dit. Backspace revient comme avant. À l’ouverture d’un nœud, le Code scrolle sur sa région.

De changement en changement

n amène le changement suivant de ce que tu regardes (le dernier atteint, la ligne cliquée, le fil visé, sinon le haut de l’écran), Shift+n le précédent. Un changement replié, ou un nœud que la vue masque, n’est pas une étape ; en côte à côte, ses deux côtés arrivent ensemble. Au bout, n ouvre le nœud touché suivant de l’Arbre sur son premier changement, Shift+n le précédent sur son dernier. Sans feature ou sur un fichier du ● Local, il s’arrête au bout et le dit ; un code illisible se dit, et la touche rejouée passe outre.

La colonne de relecture

Dans la marge de gauche, un trait de couleur longe certaines lignes : il dit à qui appartient cette ligne, et où en est ta relecture de ce symbole précis (les états sont dans Relire et endosser). Le nœud consulté porte un trait épais, à pleine encre ; les autres symboles du même fichier en portent un plus fin. Rien ne s’affiche quand Atlas ne sait pas à qui attribuer la ligne : sous-flaguer plutôt que peindre une appartenance inventée.

« ⟲ depuis ton endossement »

Sur un nœud marqué à revoir (le code a changé depuis que tu l’as validé — voir Relire et endosser), un bloc apparaît au-dessus du diff : ce qui a changé depuis TA relecture, plutôt que depuis le début de la feature. Le diff de la feature reste dessous, comme contexte.

Ce qu’Atlas trouve Ce que tu vois
un commit rattaché, et du changement depuis le diff exact entre ce commit et maintenant, replié à la portée du symbole
un commit rattaché, rien de changé dans ce fichier il le dit : ce qui a rendu le nœud « à revoir » a bougé ailleurs (un template, un voisin)
aucun commit rattaché (endossement ancien, ou posé sur du code pas commité) « pas de point de comparaison » — relis le diff de la feature, en dessous

Ouvrir un fichier de test

Un nœud de tests s’ouvre titres seuls, groupes et cas — un test se lit, il ne se relit pas ligne à ligne — et un chevron rouvre le corps d’un cas. Les cas qui atteignent le nœud que tu regardais restent à pleine encre, les autres s’atténuent, un test désactivé est barré (Fichiers et Inventaire).

Markdown et images

Un .md offre Code et Lecture, choix retenu ; en Lecture, ni lignes changées ni fils. Une image (svg, png, jpg, webp, gif) s’affiche sans fil ni rond ; au-delà de 10 Mo, Atlas le dit.

Les fils ancrés dans le Code

Un fil est une conversation ancrée sur une ligne précise ou sur un symbole entier (cycle de vie et Journal : Ticket, fils et Journal). Un fil ancré à une ligne s’affiche juste dessous, dans les deux rendus ; un fil symbolique, en encart en tête du code (« un fil sur ce symbole », ou son compte, « ◌ sur le symbole »). Pour en ouvrir un, clique le numéro d’une ligne dans la marge, écris, et Commenter le pose.

La première ligne d’un message, en gras, est le message. Un fil de l’IA que tu n’as pas ouvert le dit (« pas encore ouvert », un liseré) : il retient l’endossement du nœud. Chaque fil porte une rangée d’actions, ↗ Publier… en dernier — le seul geste qui sort d’Atlas :

Bouton Effet
Répondre ouvre une zone de texte, Envoyer ajoute ton message
Résoudre / Rouvrir ta décision — la question a une réponse, ou plus maintenant
Ranger / ↩ Remettre ce fil ne s’applique plus (réversible, sans effet sur la MR)
Supprimer efface le fil — rien d’autre ne le fait
↗ Publier… seulement sur un fil encore local

Un fil venu seulement de la merge request se lit, avec un lien ↗ vers sa conversation chez l’hébergeur, sans cette rangée. Un fil peut aussi se marquer « ⚠ à revoir » : la ligne à laquelle il était épinglé ne se retrouve plus dans le code affiché — un signal qui concerne le fil, pas ta relecture.

↗ Publier… n’envoie rien tout de suite : un encart interroge d’abord la merge request — laquelle, ce que ton jeton peut y faire, combien de messages partiront, dont combien de l’IA — et le bouton final ne s’active que si quelque chose peut partir.

Raccourcis

Ce qui pilote l’écran passe par la touche maîtresse Espace — la référence complète est Le clavier. La souris et la navigation restent directes.

Touche Effet
clic, ou Ctrl/⌘+clic aller à la définition d’un lien (un identifiant sans lien est inerte)
Alt+clic (sur un mot du code) usages de ce mot
Espace s d usages d’un nom
Alt+← / Alt+→ vue précédente / suivante de l’historique
n / Shift+n changement suivant / précédent, puis le nœud touché voisin
Backspace retour à ce que tu regardais avant
Échap éteint une sélection allumée, sort du côte à côte, puis referme le Code

Ce qu’Atlas ne fait pas

  • Il ne modifie jamais le code source des dépôts : il écrit un fil, et — au pied — le geste que tu poses sur un élément du Harnais.
  • Il n’exécute aucun test : la vue d’un fichier de test en lit les titres.
  • Il ne retire pas une note déjà envoyée sur une merge request — publier est un aller simple.
  • Il ne pose aucun lien sur un identifiant qu’il n’a pas prouvé : pas de fond, pas de saut, pas d’info-bulle.
  • Il ne cherche une sélection que dans le fichier affiché — ailleurs, c’est ↑ usages.

Limites connues

Un navigateur sans surbrillance CSS personnalisée compte une sélection sans l’allumer, et le dit.

Les usages se cherchent par nom, dans tous les dépôts du projet : un appel réseau identifié seulement par son URL n’y apparaît pas — ce genre de lien se lit dans l’Arbre.

Sur un gros bloc réécrit d’un tenant, l’appariement par contenu peut associer deux lignes qui se ressemblent sans être la même réécrite — le côte à côte tranche mieux à l’œil.

Le choix de la base de comparaison n’existe que dans la modale des noms : le volet Fichiers, lui, ouvre toujours contre la base déclarée.
