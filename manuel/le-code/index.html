Le Code

Le panneau de droite : le code réel du nœud que tu regardes dans l'Arbre — relu à chaque clic, jamais une copie — avec ses liens, ses fils de conversation et ce que tu en as déjà relu.

Le panneau de droite : le code réel du nœud que tu regardes dans l’Arbre — relu à chaque clic, jamais une copie — avec ses liens, ses fils de conversation et ce que tu en as déjà relu.

Il s’ouvre avec ce que tu ouvres

L’Arbre (détaillé dans L’Arbre) découpe le diff d’une feature en nœuds : une méthode, un fichier, un contrat (une surface dont d’autres dépendent). Sélectionne un nœud, et le Code affiche sa source réelle, lue dans git au moment du clic.

Tant que rien n’y est ouvert, le Code est fermé : le centre — vue d’ensemble, Arbre par flux ou par fichier — prend toute la place, et une feature s’ouvre ainsi. Un nœud cliqué ou choisi aux flèches, un lien, un fichier ouvert par son nom, un fil l’ouvrent, sur un quart de l’écran ; le réglage « large » de Config › Atlas lui rend tout ce que l’Arbre laisse. Échap ou le bouton ⟩ le referment, et le nœud tombe avec : 0, 1-4 et ? n’agissent que sur ce qui est ouvert. En mode recette, il porte le passage et reste ouvert.

L’en-tête tient en deux lignes, et reste en haut

Au-dessus du code, deux lignes restent en haut pendant que tu le fais défiler.

La première dit ce que tu lis : ←, la pastille (un c à l’encre contrat sur un contrat), le nom, sa signature (rien sur un fichier). À droite, l’état en une marque — un point (vert commité, gris codé, creux contexte, tirets prévu), modifié +12 −3, codé +4, non modifié ou prévu, puis ta lecture (· à relire, · relu, · à revoir) — et, sur un symbole, ↑ usages. Une signature qui ne tient pas là passe en tête de la seconde ligne.

La seconde dit d’où ça vient, et ce qu’on en sait.

Élément Ce qu’il montre
dépôt/…/fichier.ts:184 le dépôt, le fichier, la ligne — jamais coupés
⇄ comparé à master le diff ne part pas de la base déclarée du projet (section suivante)
· FactureService la classe du symbole
▶ POST …/orders/create l’étiquette entière d’un point d’entrée ou d’un appel réseau (plus bas)
neuf aucune ligne de ce code n’existait à la base
Atlas propose 4 — migre la base la criticité proposée par la carte
criticité · toi 3 · alice 4 les notes posées en endossant, nommées
? pas compris · toi · carol qui a dit ne pas comprendre ce code
relu aussi · alice qui d’autre l’a endossé (atténué : avant un changement du code)
atteint par 3 tests via Facture.total ▾ un clic déplie les phrases des tests au-dessus du code
preuve : migration SQL ce qui a classé un contrat ou une frontière

Le chemin garde le dépôt et le nom du fichier entiers (l’entier en info-bulle) ; trop long, il passe à la ligne entre les deux. À l’étroit cèdent, dans l’ordre : la classe, les faits (sous un … qui les montre), enfin la signature par mots entiers. Un nom ne se coupe jamais. Le dernier commit du fichier — le hash, son sujet et son scope — est au pied du code.

En dessous, ce que l’IA a compris : Ce que ça fait : (et Ce que ça faisait : au-dessus), sinon Pourquoi :, et Dit par l'IA : ; un ~ dit que c’est antérieur au dernier changement du fichier. Puis les fils du symbole, puis le code ; à l’ouverture, cet avant s’il tient dans la moitié haute du panneau, sinon le code d’abord.

Les types de la signature

La signature affichée en tête porte les mêmes encres que dans l’Arbre (Ce qui dépend de quoi) : bleu sur un type que ce nœud prend, orange sur celui qu’il rend. Tant que les enveloppes du langage ne sont pas déclarées pour ce projet, la signature reste en encre neutre : Atlas ne devine pas.

Sur un nœud-contrat, le titre nomme le contrat quand le fichier n’en déclare qu’un seul ; sinon, celui du fichier.

L’étiquette d’un endpoint

Dans l’Arbre, la ligne d’un point d’entrée HTTP ne porte que le verbe — ▶ PATCH — et celle d’un appel réseau vers un autre service, ⇄ GET : c’est ce qu’un décorateur prouve. L’étiquette entière vit ici, en tête de la seconde ligne : ▶ POST …/orders/create · v2, ou ⇄ PATCH /*/objects/customers/*. Elle n’est pas cliquable.

Ce qu’elle apporte en plus du verbe, c’est l’aveu, et il se survole : un …/ en tête dit que le préfixe global de montage n’est pas lu, un chemin complet qu’il est déclaré, un * un segment dynamique qu’Atlas n’a pas résolu.

Ce qui est écrit sans marque est prouvé. Le …/ est un manque de déclaration : seule la clé routePrefix le fait disparaître — voir Configurer un projet. La version (· v2) est posée à côté du chemin, jamais dedans.

Ouvrir un fichier, et à quoi le Code le compare

Un fichier n’arrive pas toujours par une ligne de l’Arbre. Deux recherches l’ouvrent ici : Espace s f le cherche par son nom, Espace s g cherche une chaîne dans le contenu des dépôts et ouvre le fichier à la ligne trouvée — les deux sont décrites dans Fichiers et Inventaire.

La première offre en plus la base de comparaison, l’autre bout du diff montré. Par défaut courante — la ligne de base déclarée du projet (voir Configurer un projet) ; sinon les lignes d’intégration qu’Atlas connaît — develop, master, main — moins la déclarée.

Le Code montre alors le diff de la branche courante contre cette base, et sa tête le dit : une chip « ⇄ comparé à master » — un diff pris d’un autre point ne doit jamais se lire comme celui de la feature. Son info-bulle, « base de comparaison imposée : », donne le commit exact, celui qu’on copie.

Ce que ce choix ne change pas :
le fichier lu il se lit là où il a été listé : le travail en cours pour un dépôt de la feature, sa base pour les autres
les fils ce sont ceux de la feature — ils restent, et la marge en ouvre toujours un
le projet la base déclarée ne bouge pas, et le choix ne se retient pas d’une fois sur l’autre
les autres portes un nœud de l’Arbre, un lien, un résultat d’usages ou de la recherche de contenu comparent toujours à la base déclarée, sans chip
un dépôt hors feature il n’a pas de branche courante : il s’ouvre sans comparaison, comme un dépôt où la base choisie n’existe pas

Ce qu’il affiche, et pourquoi ce n’est pas tout le fichier

Le fichier entier existe derrière l’écran, mais le Code n’en montre que ce qui appartient au nœud — sa signature, ses lignes changées, ses appels vers la suite du flux — avec quelques lignes autour pour te repérer. Chaque suite de lignes repliées tient sur une ligne qui dit ce qu’elle cache : ⋯ 4 lignes inchangées, ou … 306 lignes après ce symbole, toutes modifiées · 19 voisins · 3 relus ▸ quand d’autres symboles du fichier y vivent. Sur un nœud-fichier, ce sont ses méthodes qui se replient.

Un voisin seul est nommé — reset(), ou QuotaService { } pour un en-tête de classe — avec ta lecture (relu, à relire, à revoir). Plusieurs se déplient d’un clic ou d’Entrée (Échap replie) : un par ligne, son nom (un clic l’ouvre), ses lignes, ta lecture, puis ⋯ montrer les N lignes pour le code lui-même. Repliée, la marge dit ce qu’il reste dans la suite : à revoir, à relire, ou relu.

Dans la marge, un chevron replie chaque ligne qui ouvre un bloc, comme dans un IDE. Ces replis-là sont les tiens : ils survivent à la bascule entre unifié et côte à côte, et repartent à zéro dès que tu ouvres un autre code.

⚠️ Une ligne CHANGÉE qui n’appartient pas au nœud consulté n’apparaît jamais dans son écran : un correctif sur trois méthodes se lit en ouvrant les trois nœuds.

Rendu unifié et côte à côte

Par défaut, le Code empile les lignes façon GitLab : suppressions et ajouts l’un sous l’autre, une ligne réellement modifiée en place ressort en bleu — appariée à son ancienne version par son CONTENU, pas par sa position. Les mots qui changent dans une paire sont soulignés.

Espace d s — la touche maîtresse Espace, puis d (disposition) et s — bascule en côte à côte : la base à gauche, le résultat à droite, sur la même rangée quand les deux lignes se ressemblent assez pour une modification en place. Rejoué, il revient à l’unifié. Il prend tout l’écran — le volet gauche et le centre se replient, deux colonnes sur un quart d’écran ne se lisent pas — et en sortir les rouvre. Sans rien d’ouvert, la boîte dit rien d’ouvert à droite — ouvre un nœud.

Son voisin Espace d a donne l’écran au plein Arbre, et rejoué le rend tel qu’il était.

Les liens dans le code

Certains mots du code sont des liens : fond coloré, clic direct, aux couleurs de couche de l’Arbre. Deux familles :

  • les appels sortants de ce nœud précis, reconnus par le récepteur écrit dans le code : si Atlas a résolu customerService.update(, c’est cette occurrence-là qui devient un lien, pas les trois autres .update( de la méthode ;
  • les types, DTO, enums et constantes déclarés par un contrat que ce nœud importe — en orange.

Un clic sur un lien-méthode sélectionne ce nœud dans l’Arbre : l’Arbre se déplie jusqu’à lui, ses appelants directs se soulignent en pointillé, et le Code affiche sa source. Un lien-contrat ou une constante ouvre directement sa source — un type n’a pas forcément de ligne à lui dans l’Arbre.

Tout le reste du code est inerte. Un identifiant qu’Atlas n’a pas relié par un appel ou un import prouvé garde sa coloration de syntaxe, mais il n’a ni fond, ni saut au clic — même quand son nom existe ailleurs dans la feature. Il n’y a pas de clic « par nom » : deux .update( sur deux objets différents portent le même mot et n’appellent pas la même chose.

Aller à la définition, les usages

Un clic — simple, ou Ctrl/⌘+clic — sur un lien saute à sa définition. Maintenir Ctrl (⌘ sur Mac) allume les liens à l’écran : utile dans une ligne dense. Un survol fait apparaître une pastille qui rappelle les gestes possibles : « ⌃ clic → définition · ⌥ clic / Espace s d → usages » sur un lien, « ⌥ clic / Espace s d → usages » seul sur un appel qu’Atlas n’a pas su résoudre. Backspace revient à ce que tu regardais juste avant.

Les usages répondent à « où ce nom apparaît-il, ailleurs ? », pour n’importe quel symbole affiché. Trois portes : Espace s d (le nom sélectionné, sinon le symbole survolé, sinon celui de l’en-tête), le bouton ↑ usages, Alt+clic sur un mot. Une fenêtre s’ouvre : définition en tête, puis chaque usage à sa ligne, l’aperçu à droite. Ouvrir un usage pose aussi le curseur de l’Arbre sur la méthode qui l’utilise.

C’est une recherche de texte, pas une navigation prouvée, et l’écran le dit : la fenêtre compte « N occurrences par nom », et son pied précise « une recherche textuelle du nom (git grep, mot entier), pas une relation prouvée : à toi de juger chaque occurrence ». Il dit aussi ce qu’il a coupé : « N masquées par le filtre d’import », « N premières sur M » à 200 résultats, « aucune occurrence de « X » par nom » — ce qui n’est pas « personne ne s’en sert ».

Tu en sors par Échap ou un clic dans le vide.

Les occurrences d’une sélection

Sélectionne à la souris un texte sur une ligne du Code : ses autres occurrences dans le fichier affiché s’allument en cyan vif (unifié ou côte à côte), et la tête dit « 3 occurrences dans ce fichier », la sélection et les lignes repliées comprises. C’est une égalité de texte, pas un lien : sensible à la casse, pas un mot entier. Rien pour plusieurs lignes ni moins de 2 caractères. La sélection reste copiable ; clic ailleurs, Échap ou un autre fichier éteignent.

Le curseur de l’Arbre suit le code ouvert

Ouvrir une source sans passer par une ligne de l’Arbre — un lien du Code, l’index des contrats, le volet Fichiers, une des deux recherches, un résultat d’usages — déplace la sélection sur le nœud qui porte ce fichier. Tu lis un type dans un contrat, tu l’endosses (tu déclares l’avoir validé) sur place : 0, 1-4 et ? visent ce que tu as sous les yeux (les gestes sont dans Relire et endosser). Le fichier se marque en même temps dans le volet Fichiers : ses dossiers se déplient, sa ligne passe en gras.

Deux cas seulement font atterrir le curseur : l’identité exacte du symbole ouvert, ou, à défaut, le nœud au grain fichier du même fichier — c’est lui qui reçoit ton endossement quand tu lis un type dans un contrat. Jamais un nœud qui « ressemble ». Et quand aucun nœud ne porte le fichier ouvert — un fichier hors flux, un fichier lu depuis le panneau Git — le curseur se retire : plus aucune ligne n’est allumée, et le geste d’endossement ne part pas.

Navigation par diff

Alt+→ et Alt+← sautent d’un bloc de changement au suivant ou au précédent dans le code affiché — un bloc replié ne compte pas comme une étape. Arrivé au dernier bloc du nœud courant, Alt+→ continue vers le nœud suivant qui porte du code touché par la feature, en bouclant depuis le début de l’Arbre s’il le faut ; Alt+← fait le symétrique. À l’ouverture d’un nœud, le Code scrolle sur sa région.

La colonne de relecture

Dans la marge de gauche, un mince trait de couleur longe certaines lignes : il dit à qui appartient cette ligne, et où en est ta relecture de ce symbole précis (les états sont dans Relire et endosser). Le nœud consulté porte un trait épais, à pleine encre ; les autres symboles du même fichier en portent un plus fin. Rien ne s’affiche quand Atlas ne sait pas à qui attribuer la ligne : sous-flaguer plutôt que peindre une appartenance inventée.

« ⟲ depuis ton endossement »

Sur un nœud marqué à revoir (le code a changé depuis que tu l’as validé — voir Relire et endosser), un bloc apparaît au-dessus du diff : ce qui a changé depuis TA relecture, plutôt que depuis le début de la feature. Le diff de la feature reste dessous, intact, comme contexte.

Ce qu’Atlas trouve Ce que tu vois
un commit rattaché, et du changement depuis le diff exact entre ce commit et maintenant, replié à la portée du symbole
un commit rattaché, rien de changé dans ce fichier il le dit : ce qui a rendu le nœud « à revoir » a bougé ailleurs (un template, un voisin)
aucun commit rattaché (endossement ancien, ou posé sur du code pas commité) « pas de point de comparaison » — relis le diff de la feature, en dessous

Ouvrir un fichier de test

Un nœud de tests s’ouvre différemment : tout le fichier se replie sauf les titres des groupes et des cas — un test se lit, il ne se relit pas ligne à ligne — et un chevron rouvre le corps d’un cas. Les titres des cas qui atteignent le nœud que tu regardais restent à pleine encre, les autres s’atténuent, un test désactivé est barré. Le détail est dans Fichiers et Inventaire.

Les fils ancrés dans le Code

Un fil est une conversation ancrée sur une ligne précise ou sur un symbole entier — son cycle de vie, sa résolution et son passage par le Journal sont dans Ticket, fils et Journal. Ici : un fil ancré à une ligne s’affiche juste dessous, dans les deux rendus ; un fil symbolique apparaît en encart en tête du code (« un fil sur ce symbole », ou son compte), chacun portant la mention « ◌ sur le symbole ». Pour en ouvrir un nouveau, clique le numéro d’une ligne dans la marge, écris, et Commenter le pose.

La première ligne d’un message, en gras, est le message. Un fil de l’IA que tu n’as pas ouvert le dit (« pas encore ouvert », un liseré) : il retient l’endossement du nœud. Chaque fil porte une rangée d’actions, ↗ Publier… en dernier — le seul geste qui sort d’Atlas :

Bouton Effet
Répondre ouvre une zone de texte, Envoyer ajoute ton message
Résoudre / Rouvrir ta décision — la question a une réponse, ou plus maintenant
Ranger / ↩ Remettre ce fil ne s’applique plus (réversible, sans effet sur la MR)
Supprimer efface le fil — rien d’autre ne le fait
↗ Publier… seulement sur un fil encore local

Un fil qui vient uniquement de la merge request s’affiche pour lecture, avec un lien ↗ vers la conversation chez l’hébergeur, mais sans cette rangée. Un fil peut aussi se marquer « ⚠ à revoir » : la ligne à laquelle il était épinglé ne se retrouve plus dans le code affiché — un signal qui concerne le fil, pas ta relecture.

↗ Publier… n’envoie rien tout de suite : le clic ouvre un encart qui interroge la merge request en direct — sur laquelle ça part, ce que ton jeton a le droit d’y faire, combien de messages partiront et combien l’IA en a rédigés — et le bouton final ne s’active que si quelque chose peut partir.

Raccourcis

Ce qui pilote l’écran passe par la touche maîtresse Espace — la référence complète est Le clavier. La souris et la navigation restent directes.

Touche Effet
clic, ou Ctrl/⌘+clic aller à la définition d’un lien (un identifiant sans lien est inerte)
Alt+clic (sur un mot du code) usages de ce mot
Espace s d usages du nom sélectionné, sinon survolé, sinon affiché
Espace s f · Espace s g ouvrir un fichier par son nom (base au choix) · chercher dans le contenu
Espace d s côte à côte ⇄ unifié (et prend l’écran)
Espace d a plein Arbre — le volet gauche et le Code se replient
Alt+→ / Alt+← diff suivante / précédente, puis nœud touché suivant / précédent
Backspace retour à ce que tu regardais avant
Échap éteint une sélection allumée, sort du côte à côte, puis referme le Code

Ce qu’Atlas ne fait pas

  • Il ne modifie jamais le code source des dépôts : la seule écriture qu’il permet est un fil de conversation.
  • Il n’exécute aucun test : la vue d’un fichier de test lit des titres, elle ne lance rien.
  • Il ne retire pas une note déjà envoyée sur une merge request — publier est un aller simple.
  • Il ne pose aucun lien sur un identifiant qu’il n’a pas prouvé : pas de fond, pas de saut, pas d’info-bulle. S’il n’est pas sûr, il ne t’envoie nulle part.
  • Il ne cherche une sélection que dans le fichier affiché — ailleurs, c’est ↑ usages.

Limites connues

Un navigateur sans surbrillance CSS personnalisée dit le compte d’une sélection sans l’allumer, et le dit.

Les usages se cherchent par nom, dans tous les dépôts du projet : un appel réseau identifié seulement par son URL n’y apparaît pas — ce genre de lien se lit dans l’Arbre.

Sur un gros bloc réécrit d’un seul tenant, l’appariement par contenu peut associer des lignes qui se ressemblent sans être la même ligne réécrite — le côte à côte reste alors le plus fiable pour trancher à l’œil.

Le choix de la base de comparaison n’existe que dans la modale des noms : le volet Fichiers, lui, ouvre toujours contre la base déclarée.
